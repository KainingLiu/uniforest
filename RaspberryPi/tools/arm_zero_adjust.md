# 前臂舵机零点调整

2026-09-23：更换前臂舵机后，使用独立入口寻找原默认 90° 对应的新角度。
适用于两轮全部前臂动作；不接入比赛流程，不修改其他舵机。

## 操作

先结束比赛或其他串口控制程序，让底盘、步进停止，给前臂留出运动空间。
在树莓派项目目录运行：

```bash
cd /home/uniforest/Uniforest/RaspberryPi
.venv/bin/python -u tools/arm_zero_adjust.py
```

串口自动选择方式与 `robot.py` 一致；需要时加 `--port /dev/ttyACM0`。
Windows 在 `RaspberryPi/` 中可用 `.venv/Scripts/python.exe tools/arm_zero_adjust.py --port COM5`。

连接成功后输入角度并回车，例如 `90`、`91`、`91.5`。范围 0～180°，
最多一位小数，非法值不会发送。程序只发送前臂 S2（ID 1）角度，不启动相机、
Grap/Build、步进或底盘运动，也不在启动时主动复位舵机。
提示“A 板已接收”仅表示命令 ACK 成功，不代表有舵机位置反馈。

建议从 90° 附近小幅调整，观察前臂是否回到原来默认姿态。找到后记下输入值并
告知维护者，不必修改比赛动作中的 90°、95°、120° 等角度。
输入 `q` 或按 Ctrl+C 退出；结束时停止底盘、步进和吸盘并断开通信，不自动回转前臂。
舵机 PWM 保持最后指令；断电或 A 板重启后的姿态另受开机复位控制。
等待输入期间持续监视遥测和心跳，通信故障中止，不自动重连或继续动作。

启动时先等待本轮启动后的新遥测与心跳连续稳定 300 ms，再固定链路代次，
避免把连接握手到周期心跳的启动间隔误判为调零期间断线。进入调零后仍保留
150 ms 数据新鲜度和链路代次检查；故障不会自动恢复，报错会区分具体原因。
可先执行 `.venv/bin/python -u tools/arm_zero_adjust.py --check-link`，
仅检查启动及连续 3 秒通信，不发送舵机角度；退出仍执行既有停止与断连流程。

## 固定偏置

偏置集中在 [servo.h](../../Uniforest_A/Core/Inc/servo.h) 的
`SERVO_ARM_FRONT_OFFSET_TENTH`，单位为 0.1°，当前为 **120，即 +12°**。
2026-09-23 用户确认：新舵机输出 **102°** 对应原默认 **90°**。
本次标定基于原零偏置固件；新偏置须通过 CLion 烧录后生效，程序无法读取板上偏置。

```text
偏置 = 新默认角度 - 90°
输出角度 = 原逻辑角度 + 偏置
```

当前宏填 `120`。烧录后，“前臂 90°”输出 102°；“前臂 95°”输出 107°；
“前臂 120°”输出 132°；Build 的“前臂 0°”输出 12°。
现有 Grap/Build、数量检查的前臂逻辑范围 0～120°，补偿后 11～131°，不触及限幅。

[servo.c](../../Uniforest_A/Core/Src/servo.c) 在统一 PWM 输出层仅对 ID 1 加一次偏置。
单舵机整数/小数命令、四舵机命令、单独/全部复位、开机复位以及 A 板 Grap/Build
动作都经过该层；上位机不再加偏置，动作表保留原角度。
补偿后输出限幅到 0～180°；若补偿使动作端点超出范围，则不能完整复现该端点，
确认实际偏置后需核对全动作范围，尤其 Build 的逻辑 0°。

设置实际偏置后由用户通过 **CLion 的 OpenOCD + DAPLink** 编译烧录。
再次标定时，本工具依然发送逻辑角度，已有固件偏置也会生效；此时增量为
“本次找到的输入角度 − 90°”，应加到已有偏置上，不能把它当作绝对输出角度。

协议未变：单舵机命令 0x20，整数载荷 2 B、小数载荷 3 B（角度为大端 0.1°）；
复位 0x21、四舵机 0x22、动作状态 11 B、完整遥测 80 B 及 200 ms 通信失联急停均保持。
本工具使用既有 Robot 心跳/遥测和逐命令 ACK 校验，无新依赖。
软件检查不能替代实机验证；默认姿态已由用户确认，烧录状态及全动作补偿效果待复测。
正常 PONG 日志已关闭；50 ms 心跳继续发送，发送失败或响应超过 200 ms 时提示，
同一持续异常只提示一次，不自动恢复已中止的动作。调零工具自身仍保留 150 ms 检查。
