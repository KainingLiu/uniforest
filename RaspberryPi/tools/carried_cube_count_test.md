# 方块携带数量检查与标定

文档更新：2026-09-26；识别特征版本 feature_version=4。按用户要求，仅使用画面下方 30% 的
橙色宽度判断数量；640×480 时 ROI 为 x=0..639、y=336..479。上方 70% 的颜色、
亮度、方块顶边位置不参与任何计数或紫色判定。旧版标定和问题见 [CHANGELOG.md](../CHANGELOG.md)。
已接入 Task1/Task2 两轮橙色抓取阶段；tools/carried_cube_count_test.py 保留为独立
标定入口。两者共用本配置和识别模块。依赖沿用 NumPy、OpenCV、pyserial。
用户操作实机，助手仅更新代码及离线回放；比赛中的组合流程尚待现场验证。

## 比赛流程

完成原定橙色抓取批次后检查：Task1 原定 3 次，Task2 有紫色时原定 2 次、
无紫色时 3 次。结果为 3 或 null 则继续后续路线；结果为 0/1/2 则分别补抓
3/2/1 个橙色方块，再检查，直到满足条件或搜索距离耗尽。补抓沿用 Task1 Grap3、
Task2 Grap1 及原搜索/粗调/精调/压墙流程，搜索距离和编码器原点不重置。
初始批次或任一补抓批次触发 SearchRangeExhausted，都跳过检查直接进入后续路线；
后续横移补偿包含所有补抓产生的编码器位移。

比赛动作由 control/carried_cube_inspection.py 执行，复用 Robot 的心跳、串口和
cube 原始帧，不启动独立测试子进程、不重复打开相机。按下表时序移动两个舵机，
丢弃姿态等待结束后的 3 张新帧，再取 8 张新帧，保持底部 30% 宽度算法不变。
正常识别（包括 null）后复位并清除检查姿态的旧检测帧；记录 carried_cube_count
诊断事件、宽度和 reason。独立入口仍另存原图，比赛入口不写每帧图片。

null 仅代表识别不确定；相机采集失败、配置错误、ACK 超时/拒绝、遥测或 PONG
超过 150 ms、A 板重启、取消和急停不会转成成功。此时急停并向上抛错，不自动
继续或发送复位舵机命令。舵机 ACK 按命令和 SEQ 匹配，动作锁排除组合动作并发。

2026-09-15 抓取到检查的衔接修正：用户实机在第三次 Grap3 后触发原单帧静止判断。
原错误没有携带忙标志/轮速，无法确定是旧步进状态还是轮速触发。比赛入口现先取
新 ACTION_DONE 状态，发送底盘零速，再等待 3 帧不同 uptime 的新遥测，要求采样时间
不早于完成状态且接收时间晚于零速命令、步进空闲、四轮绝对速度不超过 10 rpm。
最多等待 1 秒，满足即继续；不是固定增加 1 秒。失败日志明确记录 stepper_busy、
四轮 rpm 和确认帧数。通信/取消保护仍有效，未放宽轮速门限；新衔接待现场验证。
本地与远端的既有搜索实现、步进默认值差异保留，本次只合入数量检查。

## 宽度提取与标定

先截取下方 30%，用 OpenCV HSV [0,80,40]～[50,255,255] 提取橙色。选取该区域中
最大的橙色连通区域，面积不足 ROI 的 1% 则忽略。逐行求其最左至最右像素跨度，
空行记 0；144 行宽度取中位数，8 张新帧再取中位数。只比较宽度，不比较横向位置，
允许舱内左右偏移；行中位数降低局部孔洞、反光和少量未覆盖行的影响。

| 数量 | 现有实拍帧宽度范围（640 像素图宽） | 标定参考宽度 |
| --- | --- | --- |
| 0 | 0 px | 0 px |
| 1（橙色） | 233～248 px | 245.5 px，另有偏移参考 234 px |
| 2 | 382～408 px | 406 px |
| 3 | 640 px（覆盖整个图宽） | 640 px |

参考来自原已确认 0/1/2/3 块各 8 帧，以及用户确认的 23:47:49 一块偏移组。
23:47:13 误标为 3 块但实际 2 块的组仍排除训练，仅回放核对。没有自动训练。
原型 features 现在只有一维“橙色宽度 / 图像宽度”，旧版 128 维特征必须重提。
接受距离及帧间差异上限为 0.12（640 图宽时约 76.8 px），最小类别距离差为
0.02（约 12.8 px）。这些值属于新宽度特征，不能与旧外观误差数值直接比较。
同数量多参考先取最小距离；临近两类边界或偏离全部参考时返回 null，reason 记录原因。
ROI 亮度中位数低于 0.10 时返回 image_too_dark，避免黑帧直接当空仓；亮度不用于分层。

紫色计 1 的用户规则保留，也只检查下方 30%：x=250..399、y=336..479。
HSV [105,40,35]～[155,255,255]；最大紫色区域占比至少 15%，宽度至少该区域 50%、
高度至少 20%，8 帧至少 6 帧满足后返回 1。少数帧有紫色而未达一致要求则返回 null。

22 组、176 张真实照片回放均有数量输出，已有明确标签与结果相符；包含训练样本，
未附人工标签的组仍待核对，不能据此声称独立准确率 100%。原仓外干扰案例的底部
橙色宽度仍落入相应类，紫色仓内为 1、仓外紫色空仓为 0。未增加合成视觉测试。
预览图的青框是唯一计数区域，红线展示一行代表宽度；JSON 记录 orange_width_px、
逐行宽度、method=orange_width，以及 distance/margin/reason。紫色使用 purple_rule。

本参数仅在当前相机、曝光和检查姿态的真实照片上回放。3 块宽度已被画面截满，
只在 0～3 范围内使用；若移动后宽度变化、明显遮挡或仓外物体实际进入下方 30%，
仍需新实拍确认。相机姿态改变后须重新标定。继续用原入口重新摆放采样即可。

## 动作和现场状态

2026-09-24 按用户最新要求：翻转后 200 ms、前臂后 300 ms；前臂复位至 90°
并确认 ACK 后等待 200 ms，再发送翻转复位至 97.2°。固定等待合计 700 ms，
比赛两轮 Task1/Task2 和独立入口均采用；新时序尚待现场确认。
比赛结果为 3/null 时，前臂复位指令确认后立即执行后续第一段后退，复位剩余步骤
由底盘控制循环同步推进，异常立即急停。Task1 后退 400 mm、Task2 后退 100 mm，
净横移量在后退前记录，后续路线不重复后退。0/1/2 先完整复位再搜索补抓。
独立入口没有后续底盘路线，仍等待复位完成才返回。
标定配置 calibration.pose 保留原照片拍摄时的历史等待值，不能视为当前执行时序。

| 顺序 | 动作 | 参数来源 / 现场结果 |
| --- | --- | --- |
| 1 | 吸盘翻转 ID 0 → 37.2° | 用户指定，待现场验证 |
| 2 | 等待 200 ms | 用户最新指定，待现场验证 |
| 3 | 前臂 ID 1 → 120° | 用户指定，待现场验证 |
| 4 | 等待 300 ms | 用户最新指定，待现场验证 |
| 5 | 丢弃 3 帧，采集 8 张新帧并识别 | 第四版宽度实拍回放完成，待新拍验证 |
| 6 | 前臂 ID 1 → 90° | 当前 A 板复位配置 |
| 7 | 等待 200 ms | 前臂复位命令 ACK 后计时 |
| 8 | 吸盘翻转 ID 0 → 97.2° | 当前 A 板复位配置 |
| 9 | 清除检查视角的旧检测结果并返回数量 | 比赛入口；独立入口结束采样并关闭相机 |

等待从命令 ACK 后计时；ACK 不代表舵机已到位。执行前应将机构放在正常
起始位置并清空动作空间。程序检查新鲜遥测/PONG、底盘和步进空闲、组合动作
未运行，相机先成功出帧后才发送舵机命令。不会操作步进、舱门或启动吸气。
独立测试退出统一发送急停，因此会关闭吸气泵/阀；本测试不适合依靠吸盘持续吸持负载。

接收线程 + 50 ms 心跳维持通信。遥测/PONG 超过 150 ms、ACK 超时/拒绝或
检测到 A 板重启都会中止，故障锁存，不因恢复通信续跑。Ctrl+C 也不自动复位。
这些情况下 A 板保持最后舵机 PWM，需现场处理机构位置。单纯相机/分析失败且
通信仍健康时，先前臂复位、等待 200 ms、再翻转复位。相机读取在后台进行，
采集最多等待 4 秒，跳过进入拍摄阶段后的 3 帧，避免使用动作前缓存。

## 使用

先完成项目规定的 Python 检查、Debug 编译及设备检查，停止其他控制程序。
Linux 入口与桌面任务共用锁，但不保证阻止其他不使用锁的手动串口程序。

```bash
cd /home/uniforest/Uniforest/RaspberryPi
# 无设备、无动作，查看参数
.venv/bin/python tools/carried_cube_count_test.py --dry-run
# 一次完整检查；默认使用 cube 相机角色、自动选择串口
.venv/bin/python -u tools/carried_cube_count_test.py
# 装入已知数量后采集，标签只记入日志，不冒充识别结果
.venv/bin/python -u tools/carried_cube_count_test.py --known-count 2
# 离线分析保存图片，不连接串口和相机
.venv/bin/python tools/carried_cube_count_test.py --image /path/to/raw_00.png
```

每次结果保存在 `.diagnostics/carried_cube_count/日期-时间-微秒/`：
`raw_00.png` 等原始帧、`preview.png` 区域/颜色覆盖图、`result.json`。
JSON 包含动作参数、相机实际路径、请求/读取的曝光参数、完整识别配置、
人工标签、每帧特征、预测结果和失败原因。自动白平衡等参数的后端读取值
不构成已确认硬件事实。人工标签可用 0/1/2/3，预期容量依据现有 100 mm 方块
与用户给出的 100×100×300 mm 存储区；仍待现场确认。

**协议未变**：核对 Python `protocol/commands.py` / `schema.json` 与 A 板
`Core/Inc/protocol.h` / `Core/Src/protocol.c`。单舵机 `0x20` 的整数载荷 2 B、
十分之一度载荷 3 B，角度大端；ACK `0x81` 为 3 B；完整遥测 `0x80` 为 80 B；
动作查询 `0x51` 空载荷、状态 `0x83` 为 11 B；PING/PONG `0x01/0x82`；
急停 `0x02` 空载荷，CRC 小端，A 板 200 ms 失联急停不变。不新增 A 板动作 ID。
规则手册与队伍计划书未在当前工作区找到，本入口只实现用户指定的独立检查。
