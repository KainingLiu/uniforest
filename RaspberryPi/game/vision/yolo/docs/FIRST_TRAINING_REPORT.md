# collection.zip 首轮 YOLO 方块实例分割训练

日期：2026-09-27。此轮只处理离线采集图像和训练，不改变比赛程序的视觉后端。

## 数据与审阅

源档案为项目根目录 `collection.zip`，SHA256：
`b9b794acd38bf2607ea9bc51b151d3eba90e8a3d908a75870a384c7b61bfd0dc`。
安全导入后有 9 个有图像的采集会话、418 张 640×480 `cube` 摄像头原图，
均带未标注侧车元数据。场景为抓取前橙色、紫色搜索/对准；没有建筑堆叠样本。

`scripts/auto_annotate.py` 使用颜色连通域和亮度接缝生成逐实例候选掩膜。
对全部 27 张编号 4×4 叠图逐格目视审阅，手、机器人、远处橙色物及方块边界
不清的帧进入排除清单。审阅决定记录在
[`collection_20260926_review_plan.json`](collection_20260926_review_plan.json)。
结果为 309 张有实例的通过图、27 张确认空目标的负样本、82 张排除图。
此轮通过标签仍来自人工筛选的颜色候选，多边形边缘精度受候选算法限制。

以完整采集会话分组；最后一个会话只用作独立测试，倒数第二个会话用于验证。
按灰度 pHash 汉明距离 ≤5 剔除跨集合近重复图，另有 48 张已审阅图不进入训练/评估。
最终为训练 229 张、验证 30 张、测试 29 张；训练实例橙色 235、紫色 68，
验证实例橙色 28、紫色 9，测试实例橙色 45、紫色 12。
划分及逐图标签保存于本地 `data/collection/collection_v1/`。
同一场地与相近拍摄时段仍限制了泛化结论，pHash 过滤只处理高度相似帧。

## 训练与权重选择

采用官方 `yolo11n-seg.pt` 预训练分割权重，输入 320×320，批量 16，
随机种子 2026，AdamW、权重衰减 0.0005。首阶段冻结前 10 层训练 8 轮，
初始学习率 0.001；第二阶段全模型微调，初始学习率 0.0002，
最多 50 轮，12 轮无改进早停，实际运行 37 轮。
禁用色相变化、Mosaic、MixUp 和 Copy-Paste，保留轻微亮度、饱和度、
旋转、平移与缩放增强。使用 Python 3.12.14、PyTorch 2.11.0+cu128、
Ultralytics 8.4.163、OpenCV 5.0.0，在 RTX 5070 Laptop GPU 上训练。
具体配置、损失曲线和检查点位于本地 `runs/collection_v1/`。

按验证集掩膜质量和逐图实例数量选择冻结阶段 `stage1_frozen/weights/best.pt`，
并复制为本地 `models/cube_collection_v1.pt`：

| 验证集 30 张 | 冻结阶段最佳权重 | 全模型微调最佳权重 |
| --- | ---: | ---: |
| Mask mAP50-95 | 0.864 | 0.849 |
| 置信度 0.25 时实例数量不符的图 | 0 | 3 |

全模型微调权重保留供后续分析；本轮独立测试仅运行选中的冻结阶段权重。
选中权重 SHA256：
`3ecf159d55a8b3e3ce967c38a468d6b9bf0a27484fc5ab91542c9b12cc021351`。

## 独立测试

在 29 张保留图、57 个实例上的 Ultralytics 分割评估：

| 指标 | 总体 | 橙色 | 紫色 |
| --- | ---: | ---: | ---: |
| Mask mAP50 | 0.988 | 0.981 | 0.995 |
| Mask mAP50-95 | 0.826 | 0.810 | 0.843 |
| Box mAP50-95 | 0.841 | 0.772 | 0.911 |

总体 Mask precision 0.979、recall 0.977。置信度 0.25、NMS IoU 0.5 下，
27/29 张图的橙紫实例数量完全吻合；有多个橙色实例的图为 16/17 张吻合，
有多个紫色实例的图为 4/5 张吻合。
两处漏检分别是测试会话 `000019.jpg` 右侧相邻橙块、`000035.jpg`
左边缘仅露出小部分的紫块。测试叠图和逐图计数在本地
`runs/collection_v1/test_evaluation/`，其 `summary.json` 记录完整指标和权重哈希。

训练后又将权重在全部 336 张可用的已审阅图上与标签逐张比较实例数量。
12 张出现数量分歧：`42、92、131、180、182、184、216、221、310、311、396、412`。
复看这 12 张原分辨率标注叠图后，均确认标签内有相应可见方块；
分歧为模型漏检，主要发生在紧贴方块或画面边缘。此次复核没有修改标签，
也没有使用测试集结果继续调参。

这些数字反映本批图像与审阅标签的一致性。建筑堆叠、不同光照/场地、
运动模糊、实际抓取坐标和树莓派实时性能仍需单独采集与验证；当前权重未接入
比赛视觉后端，也未部署到树莓派。

## 复现入口

在 `RaspberryPi/` 下使用兼容 CUDA 的 PyTorch 环境运行：

```powershell
python vision/yolo/scripts/import_collection.py
python vision/yolo/scripts/auto_annotate.py
# 核对候选叠图，维护 docs/collection_20260926_review_plan.json
python vision/yolo/scripts/finalize_reviews.py
python vision/yolo/scripts/train_collection.py
python vision/yolo/scripts/evaluate_collection.py
```

导入脚本可先加 `--check-only` 核对原档案。本轮数据、模型和运行日志均按
`vision/yolo/.gitignore` 留在本机；脚本、审阅清单与本报告纳入源码管理。
协议未变：双方命令编号、载荷长度、字节序、遥测布局及 A 板 200 ms 通信失联急停均未修改。
