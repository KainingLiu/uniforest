`python -m simulation.navigation_verify` 生成沿墙端点/中间点有向配对、随机位置与视觉异常报告。

## 整局比赛入口

`python -m simulation` 现在默认生成 PlanA/PlanB 整局回放。打开同一个
`simulation/output/simulator.html`，选择策略后点击“从启动区运行整局”。
每局以同一个起点开始，位姿、携带物和场上暂存/建筑连续传递，包含当前计划的所有功能动作与条件跳过。
先前的独立路线对比保留在 `curves.html`；重新生成分段对比使用 `python -m simulation --routes-only`。

整局是**名义流程仿真**：实际计划与路线读取自源码，搜块成功、视觉对准、物资摆位和机构时长使用显式假设。
名义锚点纠正也通过连续移动执行，不能重置机器人位姿。它尚未复现完整视觉算法、真实接触力、
所有并行衔接时序或对手影响；完整播放不等于实机比赛闭环通过。

`match-report.json` 保存动作时间线、完整状态变更、稳定方块 ID、名义校正记录和几何检查。
初始共 20 个橙块、3 个紫块，每块始终归属于材料区、携带、暂存、建筑或遗失之一。
名义全成功时 PlanA 三次 Build 后剩 5 橙，PlanB 两次 Build 后剩 10 橙和 1 紫。
六层来源是先卸下的三块基座加上 Build 放置的三块；缺少基座或装载材料不会凭空补齐。
新增整局测试 17 项和全量 319 项测试已通过。浏览器已从头播放到 PlanA 的第 109 个动作，
显示三次搭建、空载和材料区剩余五橙；PlanB 完整结果也已生成并核对。
默认名义输入下 PlanA/PlanB 各有 51/42 次额外锚点纠正、13/21 段平面包络干涉。
纠正动作与假设机构等待均计入虚拟时间，因此页面 428.70/345.44 s 不代表真实比赛成绩。

## 运行

在 `RaspberryPi/` 使用项目 Python 环境：

```bash
python -m simulation
```

Windows 当前可用环境：

```powershell
& 'vision/yolo/.venv/Scripts/python.exe' -m simulation
```

随后打开 `simulation/output/simulator.html`，无需网络资源即可播放完整比赛。
也可从输出目录启动 `python -m http.server 8765 --bind 127.0.0.1`，访问
`http://127.0.0.1:8765/simulator.html`。新增环境复用现有 NumPy、控制模块导入依赖，无新依赖。

输出内容：

- `simulator.html`：可离线打开的交互仿真，支持立体/俯视/局部/车辆视图、播放暂停、时间进度、倍速和有限轮播。
- `match-report.json`：整局 PlanA/PlanB 动作、车位、方块账本、里程碑与假设。
- `report.json`：使用 `--routes-only` 生成的 84 次分段仿真完整指标、轨迹、来源、参数和干涉检查。
- `summary.md`：逐案例结果表。
- `fragment.html`：同数据的内嵌预览源。

输出目录被本模块 `.gitignore` 忽略；源码、简化模型和测试保留。重新运行会更新输出。
可以用 `--output <目录>` 指定输出，`--max-points 20..150` 调整展示采样数；
`--inline <绝对路径.html>` 额外保存小于 1 MB 的预览。完整虚拟控制循环不随展示采样数量变化。

## 模型和覆盖

场地来自仓库 `场地图v_1.0.glb` 及规则 PDF，外框 4800×7200 mm。
22 个简化区域包括围挡、两侧高台/坡道/材料台/搭建台/启动区和材料凹槽。
源数据差异、坐标转换和几何复现见 [field_sources.md](field_sources.md)。

机器人来自计划书链接 <https://ustclty.github.io/2026RoboGame/> 中的原始 `assembly.glb`。
提取 158 个零件的包围盒用于轻量显示，未把网站显示归一化当成真实尺寸。
原始 CAD 外包约 721.33×443.15×584.56 mm；轮组中心之前/后伸出约 466.94/254.39 mm。
源 SHA-256 在 `robot_model.json`。该网站展示夹爪版，当前吸盘机构的差异仍待核对。
`arm_extension_mm=270` 只记录当前抓取命令行程，未额外加到默认整车碰撞包络，避免重复计算旧 CAD 伸出。

覆盖现有 `CURVE_ROUTES` 的 **15 类路线、28 个合法 profile/route 配对**，关联 PlanA/PlanB 使用位置。
每组实际运行三次，共 **84 次**：

1. 原几何逐段停走：执行实际 `ROUTES` 编排，每段由共同的仿真控制器完成并停车。
2. 平滑原路候选：使用原几何拐点生成 Hermite 曲线，调用真实 `run_curve` 和 `follow_trajectory`。
3. 终点捷径候选：起终点直接形成连续曲线，保留该路线规定的墙接触边界和已知尾段。

路线参数、已有提前后退标志、补偿公式从当前源码读取。搜块位移输入暂设
地面橙 300 mm、高地橙 300 mm、紫块 −100 mm；均为场景假设。
两个橙块运输路线默认已完成检查后的直线退离，与当前计划的衔接顺序一致。

## 动力学与时间比较

四个轮电机使用一阶响应，时间常数 0.08 s；通过实际麦轮运动学驱动位置，
编码器量化和 IMU 角度提供控制反馈。真实位置和里程计分开保存，允许注入横向打滑用于测试。
控制器与真值都用虚拟时间运行，不执行真实 sleep。

默认假设：平移上限 600 mm/s、指令加速度 800 mm/s²、角速度 90°/s、
角加速度 140°/s²、单轮上限 3000 RPM、周期 20 ms；无打滑。
这些数值专用于比较，尚未经过实机标定。内存中的 validated 标志仅用于绑定虚拟 plant，
生成的输出均带 `simulation_only`，未生成可用于比赛的 TransitionConfig。

原几何停走基准使用同一动力学和跟踪器；未复现旧定距/转向 PID 的真实耗时。
靠墙的未知行程、堵转等待、视觉、抓取和舵机时长省略，因此结果只比较已知移动段。
完整路线终点仍停车，中间曲线不保证时间最优或最短距离。

## 场地摆位和碰撞边界

生产代码中的 anchor 是名称和局部路线约定，缺少对应 CAD 全局位姿。
每条路线使用 `__main__.py:demo_start` 显式指定的独立演示起点；三种方式共享该起点。
这份输出未拼装成整场比赛的全局轨迹，也未按碰撞结果自动平移路线来掩盖冲突。

干涉检查使用轮组中心前后非对称整车外包与场地障碍多边形，包含转向角点及点间保守扫掠。
坡道和高台设为可行驶面；坡道高度只用于显示，未模拟俯仰、重力或跨越高台边缘的可行性。
平面投影可能把高处零件越过低台判为干涉，需要进一步做真正的三维高度检查。
碰撞检测在运动仿真之后执行，没有碰撞力或接触响应；出现干涉的运动仍会播放，并显示标记。

控制完成和无干涉是两个独立结果。未检出干涉也不构成现场通行证明；
展示轨迹下采样后检查，仍存在采样误差。没有模拟对手、摩擦、载荷、吸盘、机构摆动或视觉延迟。
