# 统一动作执行契约

2026-10-01：PlanA/PlanB 整套平铺动作已通过统一执行器；没有旧 Task 执行链。
主入口与模块图见 [策略说明](../README.md)。以下均为本机代码状态，尚未实机验证。

## 编译与段替换

Action 有 enter/body/exit/precondition/context。plans 只输出 ActionSpec，flows.factory
将其绑定为可执行 Action；runner 对整套计划调用一次 compile/run。
匹配 T(A,B) 时完整替换 A.exit 与 B.enter；否则 A.exit → 停车 → B.enter。
下一主体前检查前提，最后退出后停车，故障关闭整个执行上下文。

compile_flow 固定候选衔接，运行到边上才按上下文匹配和优先级选择。
不自动求解最优轨迹，也不自动推导机构净空；每种专门衔接要单独实现、验证。
目前登记了抓取→下一块、抓紫→转场、最后一抓→退离、检查→运输及 Build→返程。
新增抓取衔接需要 transition_config 中的现场记录和配套固件声明；默认未启用。
字段和逐项验证方法见 [衔接配置](../TRANSITIONS.md)。

## 抓取与检查的段替换

抓取 enter 启动持锁会话并隔离相机；body 维持原顶墙动作并等完整抬升；
exit 等机构 DONE、复位等待和会话关闭。T 可以从 body 结束时提前接管底盘。

- 抓取→下一块：有限右盲移；复位后收到同姿态代次的新帧，将编码器实测速度交给
  pickup_motion 的搜索/对准控制。两者共用底盘控制者与原采集区搜索预算，中间不插停车。
  新目标已对准时下一 acquire 主体只消费结果；视觉失败则停止并回到原搜索流程。
- 最后一抓→检查：收臂期间先执行本轮原直线后退，记录实际退距与已退离标志。
  有紫块时跳过未使用的第三橙块槽，仍能提前退离；检查少块则完成复位并释放锁后，
  按实测距离返回、顶墙重标、补抓。后续路线消费标志，避免重复后退。
- 抓紫→转场：完整抬升后监督同一机构会话并运行 purple_to_orange，最后汇合。
- 检查→运输：计数完成即开始原直线后退，同时推进复位；完成复位和解锁后才转弯或执行曲线。
  未提前退离且确认少块时原地补抓；检查图像未知仍沿用原有视觉降级语义。

## Build 与路线重叠

```text
Build.enter：启动机构会话，屏蔽相机几何
Build.body：等第三块释放
Build.exit：等机构收尾，关闭会话
Navigate.enter：执行已标定返程
T(Build,Navigate)：监督机构的同时运行返程，然后等机构收尾
Navigate.body：检查运行状态并更新路线出口锚点
```

未重复执行被替换的两段。再次装载前保证机构与返程都结束。
路线默认使用原分段移动/转向控制；配置了曲线的路线由 flows.curves 适配。
control.trajectory 用局部三次 Hermite 曲线同时跟踪位置与连续航向，中间航点不强制停车；
速度、加速度、轮速、跟踪误差和遥测时效均有限制。沿用编码器补偿的实际出口，
保留接墙/重标等边界；路线终点停车确认。尚无自动避障或全局最优路线求解。

## 机构与相机

control/actions.py 的 begin() 返回持锁会话，具有 check、wait_chassis_ready、wait_done、close、abort。
移动期间调用同一会话检查；异常清理保留原故障，不允许迟到回调恢复运动。

固件源码中 Grap1/2/3 在完整抬升段结束后发布状态6，Build 在第三块释放后发布。
抓取上位机 pickup_full_lift_validated 默认 False，兼容旧固件时等待 DONE；
验证匹配固件和实际净空后才能提前移动。脉冲完成仍不能证明没有失步或吸取成功。

相机 begin/end 姿态接口隔离缓存、在途结果与不同姿态代次的新帧。
普通抓取沿用 post_grab_settle_s（默认0），启用新衔接时使用现场标定的 arm_restore_s，
从观察到 DONE 开始计时。它属于复位时间估计；舵机无角度反馈，可靠水平检测仍未实现。
盲移接管同时要求复位时间已过、同代次且晚于复位的新帧及新鲜遥测。

## 盲移原语

blind.run_blind_transition 已由 flows.transitions 接入 Grap3/Grap1→下一橙块，
需要显式现场验证的配置。方块完全抬升和复位依据均来自同一抓取会话。
完整抬升后才可运动；位移、速度、帧时间、遥测时间和指令延迟参与限制与制动。
复位证据与同代次新帧满足后把实际速度交给下个控制过程；其他普通退出停车，
遥测陈旧、错误动作标识、取消或发送失败为硬故障。
后续视觉控制已支持实测非零初速度；最终到块时仍需低速及多帧确认。

## 恢复与验证

ExecutionContext 仅保存一次执行内的航向、锚点、动作和通信连续性。
世界模型与持久化未实现，急停后关闭当前执行，不能自动续跑。
后续按已确定的规则保存建筑、材料观察与归还位置，再从启动区重新规划。

本轮衔接与 Task 移除协议未变，也未新增下位机修改。前一阶段更新的状态6语义和目标轮速清除仍需配套验证。
Python 导入、整局路线回放、控制器测试与固件主机测试均属无硬件验证；
实机前还需 ARM Debug 构建、CLion 烧录、串口/相机/标定检查及小范围动作。
