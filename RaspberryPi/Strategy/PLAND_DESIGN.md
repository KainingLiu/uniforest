# PlanD 设计与实现

日期：2026-10-04。软件已实现；低层视觉标定、机构净空和落料稳定性待现场确认。
基线为远端 `519b606`，含 PlanC 与单次跨区补抓。本轮仅修改主程序，不改 game 或历史备份。

## 1. 入口与路线

```bash
python main.py --strategy PlanD --show-plan
python main.py --strategy PlanD
```

第一条仅预览，第二条会连接并控制机器人。`pland` 为别名，Agent 可调用
`run_strategy(selection="PlanD")`。桌面安装脚本新增 PlanD 快捷方式，沿用原互斥锁和日志。
本次未在树莓派安装；默认策略仍为 PlanA。

PlanD 直接复用 PlanB 的不可变任务列表：

```text
task0-2 → task2-1 → task4-1 → task2-2 → task4-2
→ task0-3 → task1-1 → task0-3 → task1-2 → task5
```

| 轮次 | 目标 | 去向 |
| --- | --- | --- |
| 1 | 紫橙橙，缺紫则三橙 | Task4-1 暂存第一组三块 |
| 2 | 紫橙橙，缺紫则三橙 | Task4-2 暂存第二组三块 |
| 3 | 三橙，允许最终不足三块 | Task1-1 推至搭建点 A |
| 4 | 三橙，允许最终不足三块 | Task1-2 推至搭建点 B |
| Task5 | 搬回第一、二组暂存矿 | 分别加高 A、B |

前两轮满载三块沿用用户指定的工作前提。紫矿仍按现有存取顺序最后放置。
Tag6 为路线定位参考；暂存点、推放点与加高目标分别保留现有几何关系。

## 2. 最终数量与独立记账

每次运行创建新的 `PlanDState`，独立于一次性消费的 `BuildApproach`。
`CargoResult` 保存原轮次、搭建点、视觉数量和是否补抓；A/B 分别保存观察数量、投放数量、
投放完成时刻、层数状态和加高状态。

- 普通 Task1 保存最终舱内检查结果。
- Task1-1/2 搜索耗尽时沿用退出途中检查和至多一次 Task2-0 跨区补抓，保留原轮次身份。
- PlanD Task2-0 无论完成请求次数还是再次耗尽，均在退出途中最终复检，覆盖补抓前数量；不递归补抓。
- 最终数量未知时，投放前仅额外观察一次；仍未知就保留未知。
- 原投放尾段开舱、退车、关舱成功后才提交该点记录；故障不记成功，重复提交拒绝。
- 运行关闭后拒绝使用旧状态续跑。0/1/2/3/未知均保留，不按抓取次数推算数量。

PlanD 底座记录不套用旧 Task1-0 的未知→Build2 推断；该旧规则继续服务原 Task3 路径。
额外静止复检可接受 ACTION_IDLE，同时仍要求轮速静止、双步进空闲，并拒绝异常动作状态。
记录层数依据“舱内观察 + 完成推放”；尚无视觉证明每块投放后仍竖直堆叠，日志保留此证据边界。

## 3. Task5 按目标层数搭建

用户已确认“第四次”指目标第 4 层。Task5 每个有效点仍搬三块：

| 底座层数 | 逻辑目标层 | 使用的释放姿态层 | 动作 ID | 预期总层数 |
| --- | --- | --- | --- | --- |
| 1 | 2、3、4 | 4、4、4 | 7 | 4 |
| 2 | 3、4、5 | 4、4、5 | 8 | 5 |
| 3 | 4、5、6 | 4、5、6 | 4，原 Build3 | 6 |

`Actions.build_on_base(base_height, chassis_followup=...)` 仅接受整数 1/2/3。
原 Build1/2/3 保持“本次搬几块”的含义。每组最后一块释放后才启动返程，机构和底盘全部
完成后记 `done`，然后取下一组；异常记 `interrupted`，整次停止。

0、未知或对应层标定未启用时，在取回暂存矿之前跳过该点，保留该组材料：

- A 跳过：在初始左墙等待位直接右移原有 300 mm，第二组正常加载的前顶墙重新建立纵向基准。
  不额外靠前墙、不开舱，不走 A 的 940 mm 建筑接近段。
- B 跳过：在第二加载等待位结束。该终点与完成 B 后的返程终点不同，日志明确记录。
- 一处跳过仍可处理另一处；通信、陈旧遥测、急停和机构故障均终止，不能降级为跳过后继续。

PlanD 要求建筑视觉对准成功，失效时不释放；PlanB 保留原视觉降级规则。

## 4. 固件与协议

新增 `ACTION_BUILD3_ON_BASE1=7`、`ACTION_BUILD3_ON_BASE2=8`。
三次取料终点保留原累计坐标 `(H,V)=(3.5,0)、(0,-11)、(0,-20.5)` cm。
第 4 层释放沿用 `(22.5,-19)`、前臂 4°、翻转 95.2°；第 5 层沿用 `(23,-13.5)`、
前臂 0°、翻转 97.2°。重复释放时重新计算返回下一舱位的相对轨迹，结束净位移回到入口。
完整步骤见 `Uniforest_A/ACTIONS.md`。这些为源码命令值，实际机械净空和落料效果待现场确认。

schema v5→v6，仅扩展动作枚举。双方常量、编码校验和固件分发已同步。
以下协议结构未变：CMD_ACTION_START=0x50，6 B，`>IBB`；TELEM_ACTION=0x83，11 B，
`>IBBBI`；完整遥测 80 B；字段大端、CRC 小端。A 板 200 ms 失联急停、动作取消和重连后
不续跑行为保留。上位机记账与视觉配置本身协议未变，无新增串口载荷或遥测字段。
配套固件须通过 CLion 的 OpenOCD + DAPLink 烧录。

## 5. 按层视觉标定

配置为 `Strategy/building_profiles.json`。模型仍为 `z=scale/top_row`，目标水平距离
沿用 75 mm。三层保持尺度 `132.8×82.4=10942.72`，状态 `legacy`。
一、两层默认 `unverified/null`，对应点加高会被跳过，需录入实测数据后启用。
PlanD 使用有效轮廓顶边，不回落到其他距离估计。

离线录入工具（实际命令写在同一行）：

```text
python tools/calibrate_plan_d_building.py --layer 1 --distance-mm <实测水平距离>
    --top-row-px <640x480图像的顶边行号> --date YYYY-MM-DD --result "现场观察结果"
```

默认只预览；加 `--write` 保存，第二层用 `--layer 2`。工具不调用串口、相机或动作。
输入需满足正有限距离、帧内行号、有效日期和现场记录；校验临时文件后替换，保留其他层。
完整 PlanD 开始第一项动作前检查配置，Task5 再次检查；非法文件不等到取完矿后才报错。
启用档的目标顶边行号必须满足 `1≤scale/target_z<480`，避免目标落在图像外。

人工填写的 `verified` 表示标定记录已录入，程序不验证输入真实性。单距离样本只能固定
一个点，需在 75 mm 目标附近多个距离进行静态核对，再进行小范围动作。
不得将工具成功退出写成硬件验证成功。自由落体的落点、弹跳、侧翻与回收净空另行验证。
测试中的合成尺度仅在临时文件内，不会写入现场配置。

## 6. 行为变化 → 模块 → 验收

| 行为 | 模块 | 验收 |
| --- | --- | --- |
| 策略注册与入口 | plans、runner、main、Agent、桌面工具 | 默认保留；路线复用；预览无硬件 |

## 7. 验证与现场顺序

2026-10-04 最终验证：121 个 Python 文件语法、模块导入和 231 项单测通过，无跳过，
包含本机 C 动作回放；CLI/Agent 预览、桌面 dry-run 与 Bash 语法检查通过。
已尝试 Debug 配置/构建，当前终端缺少 ARM GCC，完整固件编译未验证。
本轮未部署、烧录或执行实机动作；细节见 CHANGELOG 同日 PlanD 记录。

实机顺序：检查工作区 → 同步协议与程序 → Python 语法/无硬件测试 →
`cmake --preset Debug`、`cmake --build build/Debug` → 串口、相机角色及标定检查 →
通过 CLion 烧录配套固件 → 小范围取料、释放与落点检查 → 完整 PlanD。
每次现场调参记录日期、参数、适用层数、入口和实际结果；通信异常、遥测陈旧、急停后禁止自动续跑。

规则依据为仓库 `RoboGame2026 竞技组规则手册4_6.pdf` 第 15—16、20—21 页：携带上限、
成功搬运、紫矿以上不计分与合法搭建条件。队伍计划书第 8、10—11、19—21 页提供存矿与
推放背景；AGENTS.md 指定的 2_1 版当前缺失，机构与路线以源码为准。
记录脱离/投放时刻，现场核对至少 3 秒稳定要求与路线时间关系；本次未增加固定等待。
