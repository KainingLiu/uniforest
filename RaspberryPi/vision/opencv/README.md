# 比赛视觉与标定

整理日期：2026-10-05。本文件统一维护相机、视觉控制和降级说明；当前实现位于本目录及 `Strategy/`。
训练实验见 [YOLO 说明](../yolo/README.md)，数量判别见[携带检查](../../tools/carried_cube_count_test.md)。

## 相机角色与配置

| 角色 | 用途 | 配置入口 |
| --- | --- | --- |
| cube | 橙/紫方块、舱内计数、建筑轮廓 | `camera_settings.json`、`camera_calib.json`、`cube_detector.py` |
| tag | AprilTag 和场地定位 | `field_localizer.py`、`tag_camera_calib.json`、`field_map.json` |

两者稳定设备路径在 `camera_devices.json`，分别对应 LRCP 与 icSpring USB 摄像头。
不要依据 `/dev/video0/1` 的枚举顺序交换角色。曝光参数由各自加载链读取，cube 的曝光调整不意味着 tag 一并改变。
当前 `tag_camera_calib.json` 的 `calibrated=false`，不能将模型输出距离当作已实测标定的绝对距离。

Tag6 诊断应区分“有新画面但没检测到码”和“没有新画面”。`no_new_frame_since_alignment` 及很大的 age 指向帧新鲜度/采集恢复链路，不足以单独归因为曝光。
当前代码包含采集恢复与新帧检查，相关回放见 `tests/test_tag_camera_recovery.py`、`test_tag_diagnostics.py`。
曝光/HSV调整应保存相机角色、采样位置、原图、识别结果和前后参数，不能只记录一次成功。

## 方块识别

| 目标 | X 目标 | 粗对准窗口 | 微调窗口 |
| --- | ---: | --- | --- |
| Task1 橙色 | 0 mm | [-20, 5] mm | [-5, 5] mm |
| Task2 橙色 | 0 mm | [-20, 5] mm | [-5, 5] mm |
| Task2 紫色 | 0 mm | [-5, 5] mm | 无独立微调 |

目标统一在 `Strategy/vision_targets.py`。橙色由 `orange_cluster.py` 提取顶面簇左首方块，使用 `orange_fixed_geometry.py` 内嵌的 Task1/Task2 独立平面投影。
`task*_orange_fixed_calibration.json` 是标定记录，运行矩阵以 Python 常量为准。
当前 `orange_config.py` 两任务 X 偏置均为 0 mm，HSV 下/上界为 `(0,45,60)` / `(40,255,255)`。
换安装角、曝光或光照后需重新验证；几何门槛通过和固定置信度不等于测量准确率。

### 抓取前横向控制

- `_align_cube()` 以 30 ms 周期控制横向，前后和旋转指令为零；Z 参与目标关联。
- 基础 PID 为 **1.5 / 0 / 0**，基础输出限幅 250 mm/s。
- 距目标 ≥120 mm 的期望速度 500 mm/s，30～120 mm 随距离收缩；30 mm 内未到位期望 100 mm/s。
- 分段速度给出下限，再与基础比例输出取较大值；最终期望上限 500 mm/s。
- 静止起步 80 mm/s，加速度限制 800 mm/s²；反向先零速，进入窗口立即零速。
- 两个新帧合格确认；X/Z 跳变门槛 45/80 mm，重复、过期或未来时间戳不参与确认。
- 橙色粗对准上限 5 s，正常结束后有最长 0.5 s 微调；紫色无独立微调。
- 粗对准到上限后沿既有比赛规则尝试抓取；持续失去目标则返回搜索，视觉未知不表示抓取成功。

### 搜索与左缘回找

橙色共享本次 1800 mm 向右搜索预算，单块抓完不重置；预算累计搜索速度与实际指令时间，不计停车、回找和对准，后续补偿仍用编码器净位移。
紫色向左上限为 Task2-1 的 750 mm、Task2-2 的 650 mm。

无有效橙色目标，且足够大的橙色簇连续 3 个新帧触及 ROI 左边界时，停车 100 ms，再以 200 mm/s 向左寻找真实左缘。
截断提示在正常目标宽高比等过滤之前产生，避免整排相贴方块或裁边目标被一并过滤。
回找最多 1000 mm / 6 s，重复帧不触发；起点和重试间隔约束见 `FirstTaskConfig.orange_edge_*`。
恢复候选后停车确认并复用原对准/抓取。原图验证可用 `tools/cube_profile_probe.py`。

## Tag6 对准

Tag6 是路线修正参考，投放区不等同于建筑本体。Task1 投放变体与 Task3 各变体目标为距离 425 mm、横向 0 mm、航向 180°。
平移容差 ±8 mm、航向完成容差 ±3°，连续 4 个有效新帧完成。
位置采用 3 帧中值；平移约 50 ms 更新，陀螺仪航向独立 20 ms 更新。

| 参数 | Task1 | Task3 |
| --- | ---: | ---: |
| 前后/横向最高期望速度 | 350/280 mm/s | 260/200 mm/s |
| 前后减速区/近区 | 100/25 mm | 140/35 mm |
| 横向减速区/近区 | 80/20 mm | 100/25 mm |
| 视觉过期/丢失超时 | 0.3/1 s | 0.7/2 s |
| 总对准超时 | 12 s | 12 s |

共同平移 Kp：前后 `0.8/0.300549527`，横向 `1.2/0.300549527`，Ki/Kd=0。
Tag6 航向 PID 为 **6/0/0**、死区 ±0.5°、最高 45°/s，没有非零最低转速限幅。
平移最低非零期望 100 mm/s，加速度 300 mm/s²；旋转加速度 90°/s²。
平移合格轴立即停止，连续两帧超差才重启；航向的 ±3°只用于完成判定，±0.5°才停止纠偏。
无效画面不使用旧位置继续纠偏，重复缓存帧不累计到位确认。

## 建筑与比赛降级

Task3 在 Tag6 后先按变体横移，再用 cube 相机对准实际建筑；Task5 直接执行建筑对准。
参数在 `Task3Config`，目标 X=0、Z=75 mm，前后/横向最高 250 mm/s，加速度限制 1000 mm/s²。
机械动作和最后释放后的路线并行见[动作表](../../../Uniforest_A/ACTIONS.md)与[策略说明](../../Strategy/README.md)。

比赛视觉缺失按预算和现有超时结束该视觉环节，继续路线；搜索耗尽跳过未抓到的方块，Tag/建筑对准失败仍按既定路线/Build继续。
计数失败返回未知，补抓及 Build 数量降级规则只在策略文档维护。
视觉纠偏暂停时发零速不等于终止整场；通信、遥测陈旧、急停和机构故障始终中止，不自动续跑。

本轮未改 HSV、曝光、几何、PID 或相机恢复逻辑，协议未变。采集默认关闭，历史标定样本与现场验证记录见 [CHANGELOG.md](../../CHANGELOG.md)。
