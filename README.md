## 当前版本基线（2026-09-24）

- 两轮 Task1/Task2 普通定距平移：400 mm/s、300 ms 加速。
- 常规路线转向前馈 120°/s、起步 600 ms，剩余 40° 进入减速区，叠加位置 PID 修正限幅 ±80°/s；到位容差 ±1.5°，无额外保持。
- Task2 两轮 Tag6：目标距离 425 mm、横向 0 mm、航向 180°；容差 ±8 mm/±8 mm/±3°，无精对准，合格后停车确认 4 个新帧。平移最低期望速度 80 mm/s，前后/横向上限 260/200 mm/s。
- Task1/Task2 两轮 Tag6 均单轴合格立即零速、连续两个有效新帧超差才重启；三项合格确认 4 帧结束。两任务均取消精对准，距离/横向容差统一 ±8 mm，最低平移期望速度统一 80 mm/s。
- 长距离默认速度及第一轮 Task2 Build 后左移：1000 mm/s、800 ms 加速；Task2 起步第一轮 2500 mm、第二轮 2350 mm，以及两轮前往 Build 的 2800 mm 坡道前进，均使用 800 mm/s、800 ms 加速。
- 两轮 Task2 暂时跳过 Tag3 对准及随后的横移；转到 -90° 后直接以 400 mm/s 前进 250 mm，再以 300 mm/s 向前顶墙。
- 两轮 Task1 前进补偿基准均为 2800 mm；两轮 Task2 橙色抓取后先后退 100 mm，净右移目标均为 550 mm，均扣除对应阶段编码器实测净右移量。
- 第一轮 Task2 在 Build 最后一次释放后并行启动后退 100 mm、顺时针转 180°、左移 2500 mm、左顶墙；第二轮等 Build 完整结束后结束比赛。
- 常规顶墙 300 mm/s、最长 4 秒；短压墙 150 mm/s、最长 1 秒，与 Grap 同时启动。
- Grap1/2/3、Build 的整套机械时序在 A 板执行。schema v3 新增状态 6（机构仍忙、允许底盘继续），动作状态仍为 11 字节，完整遥测仍为 80 字节。
- Grap2 回程上升到 5 cm 后允许后续底盘路线并行；Build 在最后一次释放后允许。并行期间仍监视动作，异常整机急停。
- Grap1/2 下降和回程上升均为 18.5 cm；前臂固定偏置 +12°，逻辑 90° 对应输出 102°。两项均为 A 板源码配置，需烧录后生效，尚未收到烧录与现场复测确认。
- Grap3 最后同时上升 9 cm、水平回收 5 cm，上升到 5 cm 时复位前臂，两轴结束后全部舵机复位；吸气启动明确关闭释放阀，修复连续抓取漏气。均需更新 A 板固件。
- Grap 无动作内固定等待；Build 仅保留两次 500 ms 取件等待和三次 500 ms 分段抬臂，第三次抬臂与步进上升重叠。全部步进结束后的额外等待已删除。
- 两轮 Task1 投放开舱后等待 300 ms，关舱后不等待。
- 两轮 Task1/Task2 原定橙色抓取结束后检查数量：3 或 null 继续；0/1/2 补抓 3/2/1 块并复查。搜索距离耗尽时跳过检查，补抓不重置搜索距离和编码器原点。
- 数量判别只使用画面下方 30% 的橙色宽度，仓内紫色计 1。检查等待为翻转后 200 ms、前臂后 300 ms、前臂复位后 200 ms；先用新遥测确认静止。结果为 3/null 时，后续第一段后退与复位重叠；需要补抓时先完成复位。
- 两任务两轮橙色粗对准达到 10 秒上限后停车，跳过精对准并直接抓取；正常粗对准成功仍进行精对准，目标持续丢失 0.5 秒仍返回搜索。此项尚未同步树莓派。
- 当前源码的步进巡航目标半周期延时为 83 μs；定时器量化及参数来源见上、下位机说明。
- A 板 200 ms 通信失联时停止底盘、双步进和吸盘并取消动作，重连不会续跑原动作。

上位机必须配套动作协议版本：旧上位机会把新固件的状态 6 当作故障；新上位机搭配旧固件会等完整 DONE 后才继续底盘。固件烧录由用户通过 CLion 的 OpenOCD + DAPLink 配置完成。数量算法已用 22 组实拍照片回放；最新比赛衔接和等待时序仍待现场验证，回放不能替代完整任务实测。

部署状态（2026-09-24）：两任务两轮 Tag6 的 ±8 mm 容差、最低平移 80 mm/s、单轴合格停车，以及 Task2 紫色抓取前进 250 mm、数量检查 200/300/200 ms 和复位重叠均已定向上传树莓派。远端 69 文件语法、导入及协议检查通过，未由助手启动实机动作。最新橙色粗对准超时抓取仅更新仓库；A 板修改需另行通过 CLion 烧录。

仓库与树莓派仍保留既有橙色搜索实现、步进调试默认参数和兼容接口差异；定向上传不代表整库一致。现场日志曾确认 A 板发出状态 6，但不能据此确认最新固件参数已生效。部署、备份与验证详情见[变更记录](RaspberryPi/CHANGELOG.md)。

## 安装与无硬件验证

树莓派用户名为 `uniforest`，开发地址为 `192.168.137.50`。密码向队内管理员获取，不写入仓库、日志或文档。

在树莓派的 `RaspberryPi/` 目录执行：

```bash
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r vision/requirements.txt
python tools/check.py
```

Windows 环境、设备预检和单项测试见[上位机使用说明](RaspberryPi/README.md)。C 固件无硬件编译：

```powershell
cd Uniforest_A
cmake --preset Debug
cmake --build build/Debug
```

当前检查入口仅执行 Python 语法、依赖导入和 6 项协议格式检查；开发机可加 `--firmware` 编译 A 板，不烧录。模拟机器人、合成视觉及虚拟 C 动作测试已按用户要求移除，`--native-actions`、`--module` 已取消。历史测试数字保存在[验证记录](RaspberryPi/CHANGELOG.md)，不代表当前现场验证状态。

## 比赛与调试入口

以下命令会连接机器人；运行前先完成无硬件验证、固件更新、设备与标定检查和小范围动作测试。

```bash
python robot.py --preflight --vision --localization
python main.py --task all
python main.py --task round1
python main.py --task round2
python main.py --task task1-r2
python main.py --task task2-r2
```

`all` 按 Task0、Task1-R1、Task2-R1、Task1-R2、Task2-R2 执行；`round1` 和 `round2` 也先执行一次 Task0，再执行对应轮次 Task1、Task2，单任务入口跳过 Task0。单机械动作使用 `python action_test.py grap1|grap2|grap3|build`，实际调用时选择其中一个动作名。
