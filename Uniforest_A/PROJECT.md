# Uniforest A 板下位机技术说明

本文按当前 `Uniforest_A/` 源码和构建配置整理。下位机是树莓派控制架构中的实时执行层，不负责比赛任务编排。

文档整理于 2026-09-26。当前动作步骤集中在 [ACTIONS.md](ACTIONS.md)，
构建入口见 [README.md](README.md)，历史调参和部署记录见
[CHANGELOG.md](../RaspberryPi/CHANGELOG.md)。

## 1. 系统职责

上位机负责视觉、策略、直线位置外环、速度规划和航向保持；A 板负责：

- 接收并校验 UART7 二进制命令；
- 以 1 kHz 运行四轮 M3508 速度 PID；
- 通过 CAN1 接收 C620 反馈并累计多圈编码器；
- 驱动四路舵机和双步进电机；
- 采集 JY61P IMU 与 SBUS 数据；
- 非阻塞执行 Grap1/2/3 和 Build 机械动作，回传动作状态；
- 回传统一遥测，并在通信失联时停止底盘、双步进和吸盘，取消后续动作。

固件使用 STM32 HAL 和裸机超级循环，无 RTOS。舵机命令为即时设置，步进电机运动由 TIM7 中断非阻塞执行。

## 3. 上电与运行流程

`main()` 的当前流程：

1. 初始化 HAL、系统时钟、GPIO、CAN1 和 CAN2；
2. 初始化 M3508、舵机、步进电机和板载 LED；
3. 等待硬件稳定并将全部舵机归位；
4. 初始化 JY61P，在 500 ms 内等待有效姿态数据；
5. 初始化 SBUS 备用接收；
6. 初始化 UART7 上下位机协议；
7. 启动 TIM6 1 kHz 底盘速度环；
8. 进入约 1 kHz 主循环，更新 IMU、解析命令并发送遥测。

CAN1 电机反馈在 FIFO0 消息中断中接收和累计，不能改回依赖主循环轮询。50 Hz、80 字节 UART 遥测在 115200 波特率下会占用数毫秒，轮询 CAN 会导致三帧 FIFO 溢出并产生累计位置误差。

## 4. 上下位机协议

UART7 使用 PE8/TX、PE7/RX，115200 波特率、8N1。帧格式：

```text
SYNC(0xAA) | CMD | LEN | SEQ | DATA(N) | CRC16
```

`LEN = 5 + N`。CRC 使用 CCITT 多项式 `0x1021`，覆盖 `CMD` 到 `DATA`；CRC 两字节在线路上为小端。协议最大载荷为 80 字节。

主要命令分组：

| 范围 | 功能 |
| --- | --- |
| `0x01-0x02` | Ping、紧急停止 |
| `0x10-0x14` | 四轮速度/转矩、速度和位置 PID 参数、PID 复位 |
| `0x20-0x22` | 单舵机、舵机归位、四舵机同步设置 |
| `0x23` | 吸盘气泵/电磁阀控制 |
| `0x30-0x36` | 单/双步进动作、停止、参数、位置计数及三段交叉触发动作 |
| `0x40` | 遥测频率设置，范围 0-200 Hz |
| `0x50-0x51` | 整套动作启动（6 字节 `>IBB`：请求编号、ID、测试标志）、状态查询（0 字节） |
| `0x80-0x83` | 完整遥测、ACK、Pong、动作状态（11 字节 `>IBBBI`） |

完整遥测载荷固定为 80 字节，包含：四个电机的角度、转速、电流和温度，IMU 航向与角速度，六个 SBUS 通道，步进忙状态、系统运行时间、双步进累计位置和四轮累计编码器位置。修改结构或字节序时必须同步更新 `RaspberryPi/protocol/commands.py` 和双方测试。

任何通过 CRC 校验的上位机帧都会刷新存活计时。超过 200 ms 未收到有效帧时停止底盘、双步进和吸盘，并取消整套动作；接收轮询前先检查失联，防止新心跳掩盖已发生的通信中断。恢复有效通信后可接受新请求，但不会续跑原动作，也不会自动启动 `Remote_Control()`。

2026-09-07：Grap1/2/3、Build 已从 Python 原样迁移至 `actions.c`。动作 ID 为
1/2/3/4；当前状态为 0 idle、1 running、2 done、3 cancelled、4 timeout、5 rejected、
6 chassis_ready。状态 6 是 schema v3 新增：机构仍忙、仍占有舵机/步进/吸盘，
仅允许配套上位机执行后续底盘路线，不能作为 DONE。
状态字段依次为请求编号 uint32、ID uint8、状态 uint8、阶段 uint8、uptime uint32，
均按大端编码；拒绝启动时阶段字段为 ACK 错误码。已有命令与 80 字节遥测布局未变。
重复最后一次请求编号只返回原状态，不重启动作；运行时拒绝其他机构修改指令，
允许状态查询、底盘指令和急停；单轴停止会中止整套动作。每段步进 30 秒保护上限，
整套 120 秒；完整机械等待与交叉触发见 [ACTIONS.md](ACTIONS.md)。
测试模式 Grap 结束后额外等待 1000 ms，Build 不接受测试标志。

动作参数适用两轮比赛和独立 `robot.py --action` 入口。独立测试等待整套完成；比赛中的
Grap2 回程上升 5 cm、Build 最后释放节点允许并行路线。旧上位机遇状态 6 会急停，
新客户端配旧固件则等待 DONE；需配套同步客户端、协议、底盘监督及策略。
完整联动效果尚待现场复测，部署记录不等于实机通过。携带数量检查由上位机
编排，使用既有命令，不新增 A 板动作 ID。

## 5. 实时控制与安全边界

- TIM6 以 1 kHz 调用 `Motor3508_UpdateAllSpeedPID(0.001f)`；不要在中断中加入阻塞操作。
- TIM7 以 100 kHz 生成步进脉冲；修改优先级或耗时前必须评估丢步风险。
- 底盘位置外环位于树莓派，A 板只提供速度内环和累计编码器数据。
- 麦克纳姆轮实际横移滑移由上位机标定补偿，下位机保持统一几何换算。
- 急停命令停止底盘、双步进和吸盘，并取消整套动作；增加新执行机构时应同步检查急停覆盖范围。
- USART3 调试遥测默认关闭。只有确认串口/DAPLink 连接不冲突后才可启用。
- SBUS 已接收解析，但正式主循环不调用 `Remote_Control()`；启用前必须复核通道映射、失控保护和退出条件。

### 当前步进参数

2026-09-25 配置适用于 Grap1/2/3、Build 及默认步进命令，参数由 `stepper.h`
及 `actions.c` 四种步进调用维护；上位机独立步进默认值在 `control/stepper.py`。

| 参数 | 当前值 |
| --- | --- |
| 起步半周期参数 | 400 μs，乘 6/5 后为 480 μs，约 1042 脉冲/秒 |
| 巡航半周期参数 | 60 μs，乘 6/5 后由 TIM7 量化为 70 μs，约 7143 脉冲/秒 |
| 加速 / 减速段 | 各 400 脉冲，即 1 cm |
| 位移换算 | 400 脉冲/cm（40 脉冲/mm） |
| 完整加速段软件计时 | 约 0.224 秒 |

TIM7 每 10 μs 更新；加减速采用原 S 曲线，短于 800 脉冲时，每段按总步数的一半
限制。起步参数也用于减速低速端。以上为软件定时值，不代表实测速度或负载能力；
需 CLion 烧录后验证。协议未变：命令编号、载荷长度、字节序、遥测及急停边界保持。

### 吸盘硬件约束

- `PD12` 为气泵 PWM 电子开关输入，`PD13` 为电磁阀 PWM 电子开关输入；两路都必须输出 PWM 波形，禁止直接持续输出高电平。
- 当前两路均使用 50 Hz 舵机式 PWM：`0°` 为关闭（约 `0.5 ms` 脉宽），`180°` 为开启（约 `2.5 ms` 脉宽）。
- `gripper_close()` 启动并保持气泵 PWM；直到 `gripper_open()` 才停止气泵 PWM。
- 启动吸气时先明确写入释放阀关闭 PWM，再开启气泵；不能只清除软件关阀计时。
  2026-09-24 修复连续抓取时释放阀可能保持开启的问题，用户已确认该故障原因。
- `gripper_open()` 关闭气泵 PWM，同时启动电磁阀 PWM；电磁阀由 A 板非阻塞计时 1 秒后自动关闭，不等待主动作。
- 通信超时和急停必须同时关闭气泵与电磁阀输出。
- 上位机启动后每 50 ms 发送一次 PING 维持 200 ms 通信看门狗；动作等待期间不应因缺少控制动作帧而关闭吸盘。

## 6. 硬件调试检查

### 底盘无输出

- 确认 C620 供电、CAN_H/CAN_L、终端电阻及四个电机 ID；
- 确认上位机持续发送有效帧，避免触发 200 ms 超时；
- 检查 CAN1 FIFO0 中断是否持续收到反馈；
- 检查目标 RPM、反馈 RPM 和输出电流，而不是直接提高 PID。

### 上下位机无法通信

- 确认 UART7 为 PE8/TX、PE7/RX，线路交叉连接并共地；
- 确认双方均为 115200 8N1；
- 检查帧长度、CRC 覆盖范围以及 CRC 小端字节序；
- 若通过 CMSIS-DAP 串口连接，优先使用 Linux `/dev/serial/by-id/...` 稳定路径。

### IMU 无数据或漂移

- 确认 USART2 PD5/TX、PD6/RX 交叉连接、共地和 115200 8N1；
- 确认 JY61P 输出程序支持的帧类型；
- 等待 `IMU_IsReady()` 后再使用航向，并只在机器人静止时重设航向参考。

### 步进或舵机异常

- 先核对驱动电源、共地、方向和限位，再核对步数/角度；
- 确认遥测中的 `stepper_busy` 与累计位置是否符合命令；
- 机械卡滞时先急停，禁止仅通过提高速度或电流掩盖问题。

## 8. 文档维护

- 修改 `main.c` 入口、协议、CMake 源文件、硬件引脚或公开接口时同步更新本文；
- README 只保留入口、当前架构摘要和构建方式；
- 修改协议时必须同步更新上位机实现、测试和文档；
- 当前协议基线记录在 `../RaspberryPi/protocol/schema.json`；Windows 验证通过后，树莓派同步时应连同该 schema、Python 校验模块和测试一起复制/更新。
- 上位机策略、视觉和位置外环迭代通常不需要修改固件，但必须核对 UART 命令编号、载荷长度、字节序、遥测布局和急停边界；确认未变化时在项目记录中明确注明“协议未变”。
- 上位机新增动作参数或视觉 profile 时，应先完成无硬件测试，再按 Raspberry Pi README 的实机步骤验证；策略层的定距超时接受不等同于下位机 200 ms 通信超时豁免。
- 日常开发只修改 `Uniforest_A/`，根目录 `备份/` 中的副本默认只读；
- 历史主程序通过 Git 历史查阅，源码目录不保留未参与构建的 `.bak` 副本。
