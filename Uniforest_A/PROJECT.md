# Uniforest A 板下位机技术说明

本文按当前 `Uniforest_A/` 源码和构建配置整理。下位机是树莓派控制架构中的实时执行层，不负责比赛任务编排。

## 1. 系统职责

上位机负责视觉、策略、直线位置外环、速度规划和航向保持；A 板负责：

- 接收并校验 UART7 二进制命令；
- 以 1 kHz 运行四轮 M3508 速度 PID；
- 通过 CAN1 接收 C620 反馈并累计多圈编码器；
- 驱动四路舵机和双步进电机；
- 采集 JY61P IMU 与 SBUS 数据；
- 回传统一遥测，并在通信失联时停止底盘。

固件使用 STM32 HAL 和裸机超级循环，无 RTOS。舵机命令为即时设置，步进电机运动由 TIM7 中断非阻塞执行。

## 2. 目录结构

```text
Uniforest_A/
├─ Core/Inc, Core/Src/          业务代码与 CubeMX 生成代码
├─ Drivers/                    CMSIS 与 STM32F4 HAL
├─ cmake/stm32cubemx/          CubeMX CMake 源文件清单
├─ CMakeLists.txt              顶层构建配置
├─ CMakePresets.json           Debug/Release 预设
├─ Uniforest_A_0628.ioc        CubeMX 配置（历史文件名）
├─ STM32F427XX_FLASH.ld        链接脚本
└─ cmsis-dap.cfg, daplink.cfg  CLion/OpenOCD 调试配置
```

主要模块：

| 模块 | 职责 |
| --- | --- |
| `main.c` | 外设初始化、1 ms 主循环、TIM6 速度环中断和通信失联处理 |
| `protocol.c/.h` | UART7 收发、CRC16、命令分发、ACK 和遥测 |
| `motor3508.c/.h` | CAN1 电机反馈、四轮速度 PID、转矩输出和累计编码器 |
| `servo.c/.h` | TIM2/TIM5 四路舵机 PWM 与归位 |
| `stepper.c/.h` | 双步进电机梯形加减速、重叠动作和累计位置 |
| `imu.c/.h` | USART2 JY61P 数据解析与航向数据 |
| `remote_control.c/.h` | USART1 SBUS 接收和备用遥控逻辑 |
| `debug_telem.c/.h` | USART3 VOFA+ JustFloat 调试输出，正式入口默认不启用 |

## 3. 上电与运行流程

`main()` 的当前流程：

1. 初始化 HAL、系统时钟、GPIO、CAN1 和 CAN2；
2. 初始化 M3508、舵机、步进电机和板载 LED；
3. 等待硬件稳定并将全部舵机归位；
4. 初始化 JY61P，在 500 ms 内等待有效姿态数据；
5. 初始化 SBUS 备用接收；
6. 初始化 UART7 上下位机协议；
7. 启动 TIM6 1 kHz 底盘速度环；
8. 进入约 1 kHz 主循环，更新 IMU、解析命令并发送遥测。

CAN1 电机反馈在 FIFO0 消息中断中接收和累计，不能改回依赖主循环轮询。50 Hz、80 字节 UART 遥测在 115200 波特率下会占用数毫秒，轮询 CAN 会导致三帧 FIFO 溢出并产生累计位置误差。

## 4. 上下位机协议

UART7 使用 PE8/TX、PE7/RX，115200 波特率、8N1。帧格式：

```text
SYNC(0xAA) | CMD | LEN | SEQ | DATA(N) | CRC16
```

`LEN = 5 + N`。CRC 使用 CCITT 多项式 `0x1021`，覆盖 `CMD` 到 `DATA`；CRC 两字节在线路上为小端。协议最大载荷为 80 字节。

主要命令分组：

| 范围 | 功能 |
| --- | --- |
| `0x01-0x02` | Ping、紧急停止 |
| `0x10-0x14` | 四轮速度/转矩、速度和位置 PID 参数、PID 复位 |
| `0x20-0x22` | 单舵机、舵机归位、四舵机同步设置 |
| `0x30-0x36` | 单/双步进动作、停止、参数、位置计数及三段交叉触发动作 |
| `0x40` | 遥测频率设置，范围 0-200 Hz |
| `0x80-0x82` | 完整遥测、ACK、Pong |

完整遥测载荷固定为 80 字节，包含：四个电机的角度、转速、电流和温度，IMU 航向与角速度，六个 SBUS 通道，步进忙状态、系统运行时间、双步进累计位置和四轮累计编码器位置。修改结构或字节序时必须同步更新 `RaspberryPi/protocol/commands.py` 和双方测试。

任何通过 CRC 校验的上位机帧都会刷新存活计时。超过 200 ms 未收到有效帧时，主循环调用 `Motor3508_StopAll()` 并闪烁红灯；恢复有效通信后继续接受命令。通信超时当前只直接停止底盘，不自动启动 `Remote_Control()`。

## 5. 实时控制与安全边界

- TIM6 以 1 kHz 调用 `Motor3508_UpdateAllSpeedPID(0.001f)`；不要在中断中加入阻塞操作。
- TIM7 以 100 kHz 生成步进脉冲；修改优先级或耗时前必须评估丢步风险。
- 底盘位置外环位于树莓派，A 板只提供速度内环和累计编码器数据。
- 麦克纳姆轮实际横移滑移由上位机标定补偿，下位机保持统一几何换算。
- 急停命令停止底盘和步进电机；增加新执行机构时应同步检查急停覆盖范围。
- USART3 调试遥测默认关闭。只有确认串口/DAPLink 连接不冲突后才可启用。
- SBUS 已接收解析，但正式主循环不调用 `Remote_Control()`；启用前必须复核通道映射、失控保护和退出条件。

## 6. 硬件调试检查

### 底盘无输出

- 确认 C620 供电、CAN_H/CAN_L、终端电阻及四个电机 ID；
- 确认上位机持续发送有效帧，避免触发 200 ms 超时；
- 检查 CAN1 FIFO0 中断是否持续收到反馈；
- 检查目标 RPM、反馈 RPM 和输出电流，而不是直接提高 PID。

### 上下位机无法通信

- 确认 UART7 为 PE8/TX、PE7/RX，线路交叉连接并共地；
- 确认双方均为 115200 8N1；
- 检查帧长度、CRC 覆盖范围以及 CRC 小端字节序；
- 若通过 CMSIS-DAP 串口连接，优先使用 Linux `/dev/serial/by-id/...` 稳定路径。

### IMU 无数据或漂移

- 确认 USART2 PD5/TX、PD6/RX 交叉连接、共地和 115200 8N1；
- 确认 JY61P 输出程序支持的帧类型；
- 等待 `IMU_IsReady()` 后再使用航向，并只在机器人静止时重设航向参考。

### 步进或舵机异常

- 先核对驱动电源、共地、方向和限位，再核对步数/角度；
- 确认遥测中的 `stepper_busy` 与累计位置是否符合命令；
- 机械卡滞时先急停，禁止仅通过提高速度或电流掩盖问题。

## 7. 构建与版本命名

团队统一使用 CLion 中配置的 OpenOCD + DAPLink 工具链调试和烧录。命令行仅用于无硬件编译验证：

```powershell
cmake --preset Debug
cmake --build build/Debug
```

目录名已经统一为 `Uniforest_A`，但 `.ioc`、CMake 目标和产物仍使用历史名称 `Uniforest_A_0628`。判断当前版本以源码、Git 提交和构建配置为准。

## 8. 文档维护

- 修改 `main.c` 入口、协议、CMake 源文件、硬件引脚或公开接口时同步更新本文；
- README 只保留入口、当前架构摘要和构建方式；
- 修改协议时必须同步更新上位机实现、测试和文档；
