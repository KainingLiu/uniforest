# 当前机械动作流程

更新于 2026-09-25，以 `Core/Src/actions.c`、`servo.c` 和上位机策略为准。
距离单位为 **cm**，角度为逻辑命令值；这些参数不是已验证的实际机械位移。
前臂更换后，用户确认逻辑 90° 对应新舵机输出 102°；统一输出层增加 **+12°**，
以下所有动作角度保持原约定。偏置须通过 CLion 烧录后生效，整套动作补偿效果待复测。

## 共用约定

- 水平正向为伸出，反向为回收；垂直正向为上升，反向为下降。
- 全部舵机复位：吸盘翻转 **97.2°**、前臂 **90°**、舱门 A **63°**、B **117°**。
- 开舱：A **130°**、B **50°**。Grap 投入存储舱时先设置 A **67°**、B **113°**，再释放并复位；这些命令间没有固定等待。
- 释放：停止气泵并打开释放阀，阀由下位机非阻塞计时 1 秒后关闭。
- 开启吸气：先下发释放阀关闭 PWM，再下发气泵开启 PWM；即使上一轮释放的 1 秒计时尚未结束，也会关阀。2026-09-24 修复须重新烧录后生效。
- 每组步进仍等待运动完成，但没有完成后的额外 100 ms 等待。显式并行段按下表执行。
- 分段抬臂：前臂依次到 **50° → 28° → 14° → 6° → 目标角度**，每档等待 **90 ms**，最后额外 **50 ms**，共 **500 ms**。
- 这里的步骤编号是流程说明编号，不等于状态报文的内部 `stage` 索引。

## Grap3

1. 开启吸气，全部舵机复位；前臂到 **45°**、翻转到 **52.2°**，开舱。
2. 水平伸出 **27**，到 **17** 时启动垂直下降 **9**。
3. 两轴完成后，垂直上升 **9**；到 **5** 时启动水平回收 **21.5**。完整上升结束且水平回收到 **15** 后，垂直下降 **9**。
4. 两轴完成后，舱门 A=**67°**、B=**113°**，释放方块。
5. 同时垂直上升 **9**、水平回收剩余 **5.5**；本段上升到 **5** 时，前臂复位到逻辑 **90°**，步进继续运行。
6. 两轴完成后，全部舵机复位，结束。

动作内没有固定等待，比赛入口等待机构完整结束。
主回收与剩余回收合计 27 cm，与伸出量一致。

第 5 步前臂指令由主循环按本段步进脉冲进度触发，不等待舵机到位；两轴完成后
才执行第 6 步全部复位。当前 +12° 偏置下逻辑 90° 对应输出 102°，需烧录后生效。

## 底盘并行与安全

Grap2 回程上升 5 cm、Build 第 14 步释放后，状态变为 `ACTION_CHASSIS_READY=6`。下位机继续执行机构动作且保持忙状态；上位机约每 50 ms 查询后启动原有后续路线。此通知不表示整套动作已经完成。

- 第一轮 Task2 的 Build 有后退、转向、左移和顶墙路线，可以并行。
- 第二轮 Build 后没有底盘路线，等待 Build 完整结束后结束比赛。
- 上位机单动作入口统一为 `python robot.py --action grap1`（或 grap2/grap3/build），等待整套完成，不新增后续底盘路线或测试等待。协议中的 Grap 测试标志仍兼容，当前入口不设置该标志。
- 并行期间保持动作锁，下一次机械动作前等机构和底盘路线都结束。
- 正常转弯结束只停底盘；取消、动作故障、陈旧遥测、重启或发送失败仍整机急停。A 板运动组 30 秒、机构动作 120 秒及通信失联 200 ms 保护保持。

## Task1 三个橙色方块投放

这段由上位机编排：到达投放墙后开舱，等待 **300 ms**，以 **400 mm/s** 后退 **300 mm**，关舱后**不等待**，继续左移和转向。两轮相同；路线和两轮横移差异见[上位机说明](../RaspberryPi/README.md)。

修改本文件对应的 C 动作时序需通过 CLion 的 OpenOCD + DAPLink 配置烧录。上位机舱门等待无需烧录。当前部署和现场验证状态见[变更记录](../RaspberryPi/CHANGELOG.md)；离线检查不能代替实机确认。
